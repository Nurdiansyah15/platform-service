---
title: Onboarding company
description: Menyiapkan company pelanggan dari akun user, member, cabang, sampai role dan akses.
---

Company adalah organisasi pelanggan yang memakai solution. Halaman ini membahas langkah dari nol sampai
anggota company punya akses di sebuah solution. Setiap langkah bisa dilakukan lewat **console** (UI) atau
**API**.

**Prasyarat:** solution sudah terdaftar, katalog permission-nya sudah disinkronkan, dan backend solution
punya client. Lihat [Onboarding solution](/docs/onboarding-solution).

## Ringkasan alur

| # | Langkah | Dilakukan oleh | Console | API |
|---|---|---|---|---|
| 1 | [Buat akun user](#_1-buat-akun-user) | Platform admin | **Platform → Users** | `POST /api/v1/users` |
| 2 | [Buat company](#_2-buat-company) | Platform admin / user | **Platform → Companies**, atau halaman pilih company | `POST /api/v1/companies` |
| 3 | [Tambah anggota](#_3-tambah-anggota) | Platform admin / member aktif | Company → **Anggota** | `POST /api/v1/companies/{companyId}/members` |
| 4 | [Masuk & pilih company](#_4-masuk-pilih-company) | User | Halaman pilih company | `POST /api/v1/auth/switch-company` |
| 5 | [Tambah cabang](#_5-tambah-cabang) (opsional) | Member aktif | Company → **Cabang** | `POST /api/v1/companies/{companyId}/branches` |
| 6 | [Buat role custom](#_6-buat-role-custom) (opsional) | Member aktif | Company → **Role** | `POST /api/v1/companies/{companyId}/solutions/{solutionId}/roles` |
| 7 | [Beri role ke anggota](#_7-beri-role-ke-anggota) | Member aktif | Company → **Anggota** → detail | `POST /api/v1/companies/{companyId}/users/{userId}/role-assignments` |
| 8 | [Verifikasi akses](#_8-verifikasi-akses) | Member aktif / backend solution | Detail anggota | `POST /api/v1/authz/check` |

Contoh di halaman ini menyiapkan company **PT Maju Jaya** untuk solution **Kasir Pintar**, dengan dua
anggota: **Dewi Lestari** (pengelola company) dan **Andi Pratama** (supervisor toko di Cabang Bandung).

::note
Platform **tidak** menerapkan RBAC untuk administrasi company. Setiap member `active` boleh mengelola
anggota, cabang, dan role. Bila solution Anda butuh batasan (mis. hanya HR yang boleh menambah anggota),
cek permission solution sendiri lewat [authz check](/docs/authz) sebelum memanggil endpoint ini.
Platform admin bisa membuka company mana pun tanpa menjadi anggota.
::

## 1. Buat akun user

Registrasi publik tidak tersedia. Setiap akun dibuat oleh platform admin, dan satu akun bisa dipakai di
banyak company dan solution.

### Lewat console

1. Masuk sebagai platform admin dan buka **Platform → Users**.

   ![Menu Users di sidebar console](/images/docs/onboarding-company/01-menu-users.png)

2. Klik **Buat user**, lalu isi **Nama** dan **Email**. **Password awal** boleh diketik sendiri, dibuat
   otomatis dengan tombol **Buat**, atau dikosongkan. User tanpa password belum bisa login, dan password
   bisa di-set nanti dari halaman detail user. Biarkan **Platform admin** mati untuk karyawan pelanggan.
   Klik **Buat user**.

   ![Form buat user](/images/docs/onboarding-company/02-user-create.png)

3. Ulangi untuk setiap user. Sampaikan password awal ke user lewat jalur yang aman.

### Lewat API

```bash
curl -X POST "$PLATFORM/api/v1/users" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Dewi Lestari", "email": "dewi@majujaya.co.id", "password": "MinimalDelapan"}'
```

- `password` opsional (8–72 karakter). Tanpa password, user belum bisa login.
- `is_platform_admin` default `false`.
- Email sudah terdaftar → `409`.

## 2. Buat company

Ada dua cara membuat company:

- **Platform admin** membuat company untuk pelanggan dari **Platform → Companies**. Admin **tidak** otomatis
  menjadi anggota.
- **User biasa** membuat company sendiri dari halaman pilih company (tombol **Buat company baru**). Pembuatnya
  otomatis menjadi anggota `active`, dan company langsung dipilih sebagai company aktif.

### Lewat console (platform admin)

1. Buka **Platform → Companies**, klik **Buat company**.

   ![Halaman daftar company](/images/docs/onboarding-company/03-companies.png)

2. Isi **Nama company**. **Slug** terisi otomatis dari nama (huruf kecil, angka, dan tanda hubung) dan harus
   unik. Ubah bila perlu, lalu klik **Buat company**.

   ![Form buat company](/images/docs/onboarding-company/04-company-create.png)

3. Console membuka halaman **Anggota** company baru dengan form **Tambah anggota** yang langsung terbuka.
   Lanjutkan ke [langkah 3](#_3-tambah-anggota).

### Lewat API

```bash
curl -X POST "$PLATFORM/api/v1/companies" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "PT Maju Jaya", "slug": "pt-maju-jaya"}'
```

```json
{
  "data": {
    "id": "f7ea39db-...",
    "name": "PT Maju Jaya",
    "slug": "pt-maju-jaya",
    "status": "active",
    "created_at": "...",
    "updated_at": "...",
    "member_count": 0
  }
}
```

- `slug` sudah dipakai → `409`.
- Bila `$TOKEN` milik user biasa, user itu otomatis menjadi member `active`; lanjutkan dengan
  [switch company](/docs/login-user#_3-pilih-company-aktif).

## 3. Tambah anggota

User harus **sudah punya akun** (langkah 1). Anggota baru bisa berstatus **Aktif** (langsung punya akses)
atau **Diundang** (belum punya akses, bisa diaktifkan nanti).

### Lewat console

1. Di company, buka **Anggota** → **Tambah anggota** (form ini otomatis terbuka setelah admin membuat company).
2. Di kolom **User**, ketik minimal 3 huruf nama atau email, lalu pilih user dari daftar. Hanya user yang
   belum menjadi anggota yang muncul. Pilih **Status**, lalu klik **Tambahkan**.

   ![Form tambah anggota](/images/docs/onboarding-company/05-member-add.png)

3. Ulangi untuk anggota lain. Daftar anggota menampilkan status, jumlah role, dan tanggal bergabung. Menu
   **⋮** di setiap baris berisi **Lihat role & akses**, **Aktifkan**, dan **Keluarkan**.

   ![Daftar anggota company](/images/docs/onboarding-company/06-members.png)

Platform admin juga bisa menambahkan user ke company dari halaman detail user (**Platform → Users** → pilih
user → **Keanggotaan company** → **Tambahkan ke company**).

### Lewat API

```bash
# Opsional: cari kandidat untuk form "tambah anggota"
curl "$PLATFORM/api/v1/companies/$COMPANY_ID/member-candidates?search=dew" \
  -H "Authorization: Bearer $TOKEN"

# Tambahkan anggota (isi salah satu: user_id atau email)
curl -X POST "$PLATFORM/api/v1/companies/$COMPANY_ID/members" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email": "dewi@majujaya.co.id", "status": "active"}'
```

- `status`: `active` (default) atau `invited`.
- Sudah menjadi member `active`/`invited` → `409`. Member `inactive` akan diaktifkan kembali.
- Email tidak terdaftar → `422`.

Token service memerlukan scope `users:write`. Detail lain di [Company, member & branch](/docs/company-member-branch#member).

## 4. Masuk & pilih company

Setiap token user hanya berlaku untuk **satu company aktif** (claim `cid`). Setelah menjadi anggota, user
memilih company sebelum mengelola datanya.

### Lewat console

1. User masuk ke console dengan email dan password-nya. Bila user hanya menjadi anggota di satu company,
   console langsung memilih company itu. Bila lebih dari satu, atau user belum punya company aktif, console
   menampilkan halaman **Pilih company**. Klik company yang ingin dikelola. Dari halaman yang sama, user bisa
   membuat company baru.

   ![Halaman pilih company](/images/docs/onboarding-company/07-select-company.png)

2. Console membuka **Ringkasan** company: jumlah anggota aktif, cabang, custom role, dan penugasan role,
   ditambah pintasan **Mulai dari sini**. Menu company (Ringkasan, Anggota, Cabang, Role, Pengaturan) ada di
   sidebar. Company aktif bisa diganti lewat switcher di pojok kiri atas.

   ![Ringkasan company](/images/docs/onboarding-company/08-workspace.png)

### Lewat API

Di solution Anda, alur ini dijalankan frontend setelah login:

```bash
# Company yang bisa dipilih user
curl "$PLATFORM/api/v1/auth/companies" -H "Authorization: Bearer $TOKEN"

# Pilih company aktif → token baru dengan claim cid
curl -X POST "$PLATFORM/api/v1/auth/switch-company" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"company_id": "f7ea39db-..."}'
```

Detail lengkap di [Login user](/docs/login-user).

## 5. Tambah cabang

Cabang (branch) dipakai untuk membatasi role ke lokasi tertentu. Lewati langkah ini bila company tidak
butuh pembatasan per cabang.

### Lewat console

1. Buka **Cabang** → **Tambah cabang**. Isi **Nama** dan **Kode**. Kode unik di company, otomatis huruf besar,
   dan boleh berisi huruf, angka, `.`, `_`, `-`. Biarkan **Aktif** menyala, lalu klik **Tambah**.

   ![Form tambah cabang](/images/docs/onboarding-company/09-branch-create.png)

2. Cabang muncul di daftar. Menu **⋮** berisi **Ubah** dan **Hapus**. Menghapus cabang ikut mencabut role
   yang di-assign ke cabang tersebut.

   ![Daftar cabang](/images/docs/onboarding-company/10-branches.png)

### Lewat API

```bash
curl -X POST "$PLATFORM/api/v1/companies/$COMPANY_ID/branches" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Cabang Bandung", "code": "BDG", "status": "active"}'
```

`code` sudah dipakai di company → `409`. Token service memerlukan scope `org:write`.

## 6. Buat role custom

Role global dari solution (mis. **Kasir**) langsung tersedia di setiap company. Buat role custom bila company
butuh kombinasi permission sendiri. Role custom hanya berlaku di company pembuatnya.

### Lewat console

1. Buka **Role**, lalu pilih solution di dropdown (mis. **Kasir Pintar**). Daftar menampilkan role global dan
   custom, yang bisa difilter dengan **Semua / Global / Custom**. Klik **Buat custom role**.

   ![Daftar role company untuk satu solution](/images/docs/onboarding-company/11-roles.png)

2. Isi **Nama**; **Kode** terisi otomatis dan tidak bisa diubah setelah dibuat. Gunakan **Salin permission dari**
   untuk mulai dari role yang sudah ada (mis. role global **Kasir**). Klik **Buat role**.

   ![Form buat custom role](/images/docs/onboarding-company/12-role-create.png)

3. Di halaman role, centang permission tambahan, lalu klik **Simpan permission**. Tab **Pemegang**
   menampilkan siapa saja yang memegang role ini di company.

   ![Mengatur permission role custom](/images/docs/onboarding-company/13-role-permissions.png)

### Lewat API

```bash
# Buat role custom
curl -X POST "$PLATFORM/api/v1/companies/$COMPANY_ID/solutions/$SOLUTION_ID/roles" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"code": "supervisor_toko", "name": "Supervisor Toko", "description": "Kasir plus pembatalan transaksi dan laporan."}'

# Atur permission-nya (replace-all)
curl -X PUT "$PLATFORM/api/v1/companies/$COMPANY_ID/roles/$ROLE_ID/permissions" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"permission_codes": ["sale.create", "sale.read", "sale.void", "product.read", "report.read", "shift.manage"]}'
```

Endpoint API tidak punya opsi "salin dari role lain". Ambil permission role sumber
(`GET /api/v1/roles/{roleId}/permissions`), lalu kirim ulang `code`-nya. Token service memerlukan scope
`roles:write`. Detail di [Role](/docs/role).

## 7. Beri role ke anggota

Anggota baru belum punya permission apa pun. Role diberikan per solution, dengan cakupan **seluruh company**
(termasuk semua cabang) atau **satu cabang**.

### Lewat console

1. Buka **Anggota**, klik nama anggota (atau **⋮** → **Lihat role & akses**). Pastikan solution yang benar
   terpilih di **Role dan akses untuk solution**, lalu klik **Tambah role**. Tombol ini nonaktif bila anggota
   belum berstatus aktif.

   ![Detail anggota sebelum punya role](/images/docs/onboarding-company/14-member-detail.png)

2. Pilih **Role**, lalu tentukan **Berlaku di**: **Seluruh company**, atau **Cabang tertentu** lalu pilih
   **Cabang**. Klik **Tambahkan**.

   ![Form tambah role untuk anggota](/images/docs/onboarding-company/15-assign-role.png)

### Lewat API

```bash
curl -X POST "$PLATFORM/api/v1/companies/$COMPANY_ID/users/$USER_ID/role-assignments" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"role_id": "5e0b...", "scope_type": "branch", "scope_id": "a81e..."}'
```

- `scope_type`: `company` (default) atau `branch`. Untuk `branch`, `scope_id` wajib berisi ID cabang milik
  company.
- Cabut role: `DELETE /api/v1/role-assignments/{assignmentId}` (console: tombol **×** di samping role).

Detail di [Authz](/docs/authz).

## 8. Verifikasi akses

### Lewat console

Di halaman detail anggota, kartu **Akses (permission)** menampilkan gabungan permission dari semua role
anggota di solution terpilih. Setiap permission diberi label role dan cakupan yang memberikannya
(mis. `supervisor_toko · Cabang Bandung`).

![Role dan akses anggota setelah role diberikan](/images/docs/onboarding-company/16-member-access.png)

### Lewat API

Backend solution menegakkan izin dengan token service (scope `authz:check`):

```bash
curl -X POST "$PLATFORM/api/v1/authz/check" \
  -H "Authorization: Bearer $SERVICE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "company_id": "f7ea39db-...",
    "user_id": "3c4d...",
    "permission": "sale.void",
    "scope_type": "branch",
    "scope_id": "a81e..."
  }'
# → { "data": { "allowed": true, "granted_by": ["supervisor_toko"], ... } }
```

Untuk menampilkan atau menyembunyikan menu di frontend, ambil semua izin sekaligus:
`GET /api/v1/companies/{companyId}/users/{userId}/effective-permissions?solution_id=...`. Lihat
[Authz](/docs/authz).

## Setelah onboarding

| Kebutuhan | Console | API |
|---|---|---|
| Ubah nama / slug company | **Pengaturan** → Profil company | `PATCH /api/v1/companies/{companyId}` |
| Tangguhkan / tutup company | **Pengaturan** → Status company (platform admin) | `PATCH /api/v1/companies/{companyId}` (`status`) |
| Keluarkan anggota | **Anggota** → ⋮ → **Keluarkan** | `DELETE /api/v1/companies/{companyId}/members/{userId}` |
| Reset password user | **Platform → Users** → detail → Password | `PATCH /api/v1/users/{userId}` |

Mengeluarkan anggota **mencabut semua role-nya** di company itu. Bila diaktifkan kembali, role harus
di-assign ulang.
