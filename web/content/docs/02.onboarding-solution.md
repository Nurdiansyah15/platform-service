---
title: Onboarding solution
description: Mendaftarkan solution dan membuat solution client. Dilakukan oleh platform admin.
---

Sebelum solution bisa dipakai, **platform admin** mendaftarkannya. Langkah ini bisa dilakukan lewat
console (menu **Platform → Solutions**) atau API. Semua endpoint di halaman ini butuh token user platform
admin.

## 1. Buat solution

```bash
curl -X POST "$PLATFORM/api/v1/solutions" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "code": "hris",
    "name": "HRIS",
    "description": "Sistem HR",
    "status": "active"
  }'
```

Respons `201`:

```json
{
  "status": "success",
  "status_code": 201,
  "data": {
    "id": "6f1c0a52-...",
    "code": "hris",
    "name": "HRIS",
    "description": "Sistem HR",
    "status": "active",
    "permission_catalog_version": null,
    "created_at": "2026-10-30T08:00:00Z",
    "updated_at": "2026-10-30T08:00:00Z"
  }
}
```

- `code` **tidak bisa diubah** setelah dibuat. Nilai ini dipakai frontend saat login (`"solution": "hris"`)
  dan menjadi `aud` token user.
- Simpan `id` — dipakai di path seperti `/solutions/{solutionId}/permissions`.
- Solution `inactive` tidak bisa dipakai login, dan token service-nya ditolak.

::note
Pada deployment `on_prem`, data solution dikelola lewat license sehingga `POST /solutions` dan `PATCH /solutions/{id}`
mengembalikan `403 LICENSE_MANAGED`.
::

## 2. Buat solution client

Solution client adalah kredensial backend solution untuk mendapat [token service](/docs/service-token).

```bash
curl -X POST "$PLATFORM/api/v1/solutions/$SOLUTION_ID/clients" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "hris-backend-production",
    "scopes": ["users:read", "users:write", "org:read", "org:write", "roles:write", "authz:check", "catalog:sync"]
  }'
```

Respons `201`:

```json
{
  "data": {
    "id": "b3a7...",
    "solution_id": "6f1c0a52-...",
    "name": "hris-backend-production",
    "client_id": "cli_8d0f2c9a41b7e03d5c6f1a28",
    "client_secret": "Qk3vX9...(base64url, 43 karakter)",
    "scopes": ["users:read", "users:write", "org:read", "org:write", "roles:write", "authz:check", "catalog:sync"],
    "status": "active",
    "last_used_at": null,
    "revoked_at": null
  }
}
```

::warning
`client_secret` **hanya ditampilkan sekali** di respons ini. Platform hanya menyimpan hash-nya.
Simpan di secret manager backend solution, jangan di frontend atau repository.
::

### Memilih scope

Berikan scope seminimal mungkin. Scope yang relevan untuk fase ini:

| Scope | Untuk |
|---|---|
| `users:read` | Membaca company, member, summary |
| `users:write` | Menambah / mengubah / mengeluarkan member |
| `org:read` | Membaca branch |
| `org:write` | Mengubah company, membuat / mengubah / menghapus branch |
| `roles:write` | Mengelola role custom company dan role assignment |
| `authz:check` | `authz/check`, `check-batch`, `effective-permissions` |
| `catalog:sync` | Sinkronisasi katalog permission solution |

Scope `entitlements:read`, `usage:write`, `events:read`, dan `license:read` tersedia tapi belum relevan
(lihat [Pengantar](/docs#status-fitur)).

## 3. Kelola client

| Aksi | Endpoint |
|---|---|
| Daftar client | `GET /api/v1/solutions/{solutionId}/clients` |
| Detail | `GET /api/v1/solution-clients/{clientId}` |
| Ubah nama / scope | `PATCH /api/v1/solution-clients/{clientId}` — `scopes` menggantikan seluruh scope |
| Rotate secret | `POST /api/v1/solution-clients/{clientId}/rotate-secret` — secret baru tampil sekali, secret lama langsung tidak berlaku |
| Revoke | `POST /api/v1/solution-clients/{clientId}/revoke` — permanen |

`{clientId}` di path adalah `id` (UUID), bukan `client_id`.

Pengurangan scope dan revoke **langsung berlaku** untuk token yang sudah terbit, karena platform
memvalidasi ulang token service di setiap request.

**Rotasi tanpa downtime:** buat client kedua, deploy backend dengan kredensial baru, lalu revoke client lama.

## 4. Siapkan role global (opsional)

Platform admin bisa membuat role global (template) untuk solution, yang tersedia di semua company.
Lihat [Role](/docs/role). Role global hanya bisa berisi permission yang sudah didaftarkan lewat
[sinkronisasi permission](/docs/permission-sync), jadi lakukan sync lebih dulu.
