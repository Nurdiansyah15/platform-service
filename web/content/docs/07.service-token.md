---
title: Token service
description: Mendapatkan token mesin-ke-mesin untuk backend solution lewat OAuth2 client credentials.
---

Backend solution memakai **token service** untuk memanggil platform tanpa konteks user: sinkronisasi
katalog permission, membaca member company, mengelola role assignment, dan mengecek permission user mana pun.

## Meminta token

`POST /api/v1/oauth/token` mengikuti **RFC 6749 §4.4**. Body `application/x-www-form-urlencoded`
(JSON juga diterima).

Dengan HTTP Basic (disarankan):

```bash
curl -X POST "$PLATFORM/api/v1/oauth/token" \
  -u "$CLIENT_ID:$CLIENT_SECRET" \
  -d "grant_type=client_credentials" \
  -d "scope=authz:check users:read"
```

Atau kredensial di body:

```bash
curl -X POST "$PLATFORM/api/v1/oauth/token" \
  -d "grant_type=client_credentials" \
  -d "client_id=$CLIENT_ID" \
  -d "client_secret=$CLIENT_SECRET"
```

Respons `200` (**tanpa envelope**):

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 900,
  "scope": "authz:check users:read"
}
```

- `scope` opsional. Kosong → token mendapat **semua** scope client.
- Bila diisi, harus subset scope client; selain itu `invalid_scope`.
- Tidak ada refresh token. Minta token baru saat yang lama hampir habis.

Library OAuth2 standar (mis. `golang.org/x/oauth2/clientcredentials`, `openid-client`, Spring Security)
bisa dipakai langsung dengan token URL di atas.

## Error

Format RFC 6749 §5.2, tanpa envelope:

```json
{ "error": "invalid_client", "error_description": "client authentication failed" }
```

| `error` | Status | Penyebab |
|---|---|---|
| `invalid_request` | 400 | `grant_type` kosong |
| `unsupported_grant_type` | 400 | Selain `client_credentials` |
| `invalid_scope` | 400 | Scope tidak dikenal / melebihi scope client |
| `invalid_client` | 401 | Client tidak ada, secret salah, client di-revoke, atau solution `inactive` (sengaja tidak dibedakan) |

## Scope dan endpoint

| Scope | Endpoint |
|---|---|
| `users:read` | `GET /companies/{cid}`, `GET /companies/{cid}/members`, `GET /companies/{cid}/members/{uid}`, `GET /companies/{cid}/summary` |
| `users:write` | `POST /companies/{cid}/members`, `PATCH`/`DELETE /companies/{cid}/members/{uid}`, `GET /companies/{cid}/member-candidates` |
| `org:read` | `GET /companies/{cid}/branches` |
| `org:write` | `PATCH /companies/{cid}`, `POST /companies/{cid}/branches`, `PATCH`/`DELETE /branches/{branchId}` |
| `roles:write` | Role custom company (`/companies/{cid}/solutions/{sid}/roles`, `/companies/{cid}/roles/...`), `GET`/`POST /companies/{cid}/users/{uid}/role-assignments`, `DELETE /role-assignments/{id}` |
| `authz:check` | `POST /authz/check`, `POST /authz/check-batch`, `GET /companies/{cid}/users/{uid}/effective-permissions` |
| `catalog:sync` | `PUT /solutions/{solutionId}/permissions/sync` (hanya solution milik client) |
| *(tanpa scope)* | `GET /solutions`, `GET /solutions/{id}`, `GET /solutions/{id}/permissions`, `GET /solutions/{id}/roles`, `GET /roles/{id}`, `GET /roles/{id}/permissions` |

Semua path di atas berawalan `/api/v1`.

## Batasan token service

- Hanya bisa bekerja dengan data **solution miliknya**: role, permission, dan assignment solution lain
  tidak terlihat (dilaporkan `404`) atau ditolak.
- Selama gate subscription nonaktif, token service bisa mengakses **company mana pun**. Setelah gate aktif,
  hanya company yang berlangganan solution tersebut.
- Tidak bisa memanggil endpoint khusus user (`/auth/*`, `GET/POST /companies`, `/users/me`) maupun
  endpoint platform admin (membuat user, solution, client, role global).
- Scope kurang → `403` — *"Token service tidak memiliki scope yang dibutuhkan."*

## Rekomendasi

- Cache token di memori backend dan pakai ulang sampai ~1 menit sebelum `expires_in` habis.
- Gunakan client terpisah per environment (staging / production).
- Jangan pernah mengirim token service atau `client_secret` ke browser.
