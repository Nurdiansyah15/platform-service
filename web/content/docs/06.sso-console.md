---
title: SSO dari console
description: Masuk ke solution dari launcher console tanpa login ulang, plus menu apps di navbar solution.
---

Console platform adalah pintu masuk semua solution. User login sekali di console, memilih aplikasi di
launcher, lalu masuk ke subdomain solution dalam keadaan **sudah login**, dengan company aktif yang sama.

Mekanismenya adalah **OAuth2 authorization code + PKCE**, dengan console sebagai identity provider. Yang
dikirim lewat browser hanya **kode sekali pakai**, bukan token. Kode itu berlaku 60 detik. Token console
tidak pernah keluar dari domain console.

```text
User klik "Kasir Pintar" di launcher console
  → https://kasir.contoh.com/?company_id=…               (launch_url solution)
Solution: belum ada sesi → buat code_verifier + state
  → https://console.contoh.com/authorize?solution=kasir-pintar&redirect_uri=…&code_challenge=…&state=…
Console (sudah login): POST /api/v1/auth/authorize   → kode sekali pakai
  → https://kasir.contoh.com/auth/callback?code=…&state=…
Solution: POST /api/v1/auth/token-exchange {code, code_verifier, redirect_uri}
  → access_token (aud = kasir-pintar, cid terisi) + refresh_token
Selanjutnya sama dengan login biasa: /auth/me, /auth/refresh, /authz/check, ...
```

User yang membuka subdomain solution langsung, tanpa lewat console, mengikuti alur yang sama. Bila belum
login di console, console menampilkan halaman login dulu, lalu kembali ke solution.

## Persiapan (platform admin)

Daftarkan URL aplikasi di console: **Platform → Solutions → (solution) → Ringkasan → Tautan aplikasi (SSO)**.

| Field | Isi | Dipakai untuk |
|---|---|---|
| **URL aplikasi** (`launch_url`) | Halaman awal solution, mis. `https://kasir.contoh.com/` | Kartu di launcher dan menu apps. Solution tanpa URL ini tidak muncul. |
| **URL ikon** (`icon_url`) | Gambar persegi (opsional) | Ikon di launcher dan menu apps |
| **Redirect URI** (`redirect_uris`) | Satu per baris, maks. 10, mis. `https://kasir.contoh.com/auth/callback` | Allowlist `redirect_uri` saat authorize. Dicocokkan **persis**, termasuk query dan trailing slash. |

URL wajib `https`. Pengecualiannya `http://localhost` dan `http://127.0.0.1` untuk pengembangan lokal.

![Form tautan aplikasi solution](/images/docs/sso/03-solution-links.png)

Lewat API, kirim field yang sama di `POST /api/v1/solutions` atau `PATCH /api/v1/solutions/{solutionId}`.
Di `PATCH`, string kosong atau array kosong mengosongkan nilainya:

```bash
curl -X PATCH "$PLATFORM/api/v1/solutions/$SOLUTION_ID" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "launch_url": "https://kasir.contoh.com/",
    "icon_url": "https://kasir.contoh.com/icon.svg",
    "redirect_uris": ["https://kasir.contoh.com/auth/callback"]
  }'
```

Daftarkan juga `launch_url` milik solution console sendiri (mis. `https://console.contoh.com/`), supaya
menu apps di solution punya tombol kembali ke console.

::note
Origin (`scheme://host[:port]`) dari URL aplikasi dan setiap redirect URI solution **active** otomatis
diizinkan memanggil API platform dari browser (CORS) — tidak perlu mengubah env platform. Perubahan berlaku
langsung (paling lambat ±30 detik di instance API lain). Pastikan frontend solution berjalan di origin yang
sama dengan salah satu URL tersebut; `launch_url` console sendiri juga membuat origin console diizinkan.
Token dikirim lewat header `Authorization`, tidak lewat cookie.
::

## Dari sisi user

1. Login di console. Halaman **Ringkasan** company menampilkan bagian **Aplikasi** berisi solution yang bisa
   dibuka. Klik kartunya.

   ![Launcher aplikasi di ringkasan company](/images/docs/sso/01-launcher.png)

2. Menu apps (ikon grid di kanan atas) berisi pintasan yang sama di setiap halaman console. Aplikasi yang
   sedang dibuka ditandai.

   ![Menu apps di navbar console](/images/docs/sso/02-apps-menu.png)

3. Browser berpindah ke solution, lalu singgah sebentar di halaman **Masuk ke aplikasi** console, lalu
   kembali ke solution dalam keadaan login. Bila solution tidak menentukan company dan user punya lebih dari
   satu company, console meminta user memilih company dulu.

## Implementasi di solution

### 1. Mulai login: arahkan ke `/authorize` console

Saat solution tidak punya sesi, buat `code_verifier` acak (43–128 karakter base64url) dan `state`. Simpan
keduanya di `sessionStorage`, lalu arahkan browser ke console:

```js
const CONSOLE = 'https://console.contoh.com'
const REDIRECT_URI = 'https://kasir.contoh.com/auth/callback'

const b64url = (buf) => btoa(String.fromCharCode(...new Uint8Array(buf)))
  .replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '')

async function startLogin() {
  const verifier = b64url(crypto.getRandomValues(new Uint8Array(32)))
  const state = b64url(crypto.getRandomValues(new Uint8Array(16)))
  const challenge = b64url(await crypto.subtle.digest('SHA-256', new TextEncoder().encode(verifier)))
  sessionStorage.setItem('pkce', JSON.stringify({ verifier, state }))

  const q = new URLSearchParams({
    solution: 'kasir-pintar',
    redirect_uri: REDIRECT_URI,
    code_challenge: challenge,
    code_challenge_method: 'S256',
    state,
  })
  // Diteruskan dari launcher: masuk ke company yang sama dengan console.
  const companyId = new URLSearchParams(location.search).get('company_id')
  if (companyId) q.set('company_id', companyId)

  location.assign(`${CONSOLE}/authorize?${q}`)
}
```

Parameter `/authorize`:

| Query | Wajib | Keterangan |
|---|---|---|
| `solution` | ya | `code` solution, menjadi `aud` token |
| `redirect_uri` | ya | Harus terdaftar persis di **Redirect URI** solution |
| `code_challenge` | ya | `BASE64URL(SHA256(code_verifier))`, 43 karakter |
| `code_challenge_method` | ya | Hanya `S256` |
| `state` | disarankan | Dikembalikan apa adanya. Cocokkan di callback untuk mencegah CSRF. |
| `company_id` | tidak | Company aktif sesi baru. Bila kosong, console memakai company aktifnya, atau satu-satunya company user. |

### 2. Callback: tukar kode menjadi token

```js
async function handleCallback() {
  const p = new URLSearchParams(location.search)
  const saved = JSON.parse(sessionStorage.getItem('pkce') || 'null')
  sessionStorage.removeItem('pkce')
  if (!saved || p.get('state') !== saved.state) throw new Error('state tidak cocok')

  const res = await fetch(`${PLATFORM}/api/v1/auth/token-exchange`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ code: p.get('code'), code_verifier: saved.verifier, redirect_uri: REDIRECT_URI }),
  })
  if (!res.ok) return startLogin()   // kode kedaluwarsa / sudah dipakai → ulangi
  const { data } = await res.json()   // bentuknya sama dengan respons POST /auth/login
  saveTokens(data)
  history.replaceState(null, '', '/') // buang ?code= dari URL
}
```

Endpoint yang sama lewat `curl`:

```bash
curl -X POST "$PLATFORM/api/v1/auth/token-exchange" \
  -H "Content-Type: application/json" \
  -d '{"code": "Vx3…", "code_verifier": "dBjftJeZ4CVP…", "redirect_uri": "https://kasir.contoh.com/auth/callback"}'
```

Respons sukses identik dengan [login](/docs/login-user#_1-login): `access_token`, `refresh_token`,
`session_id`, `company_id`. Sesi baru ini milik solution (`aud = kasir-pintar`). Karena itu, refresh,
[pindah company](/docs/login-user#_3-pilih-company-aktif), dan [authz](/docs/authz) berjalan persis seperti
sesi hasil login password.

Semua kegagalan menghasilkan `400` dengan pesan yang sama. Penyebabnya bisa kode tidak dikenal, sudah
dipakai, lewat 60 detik, `code_verifier` salah, `redirect_uri` berbeda, sesi console sudah logout, atau
user dan company tidak lagi aktif. Tanggapi `400` dengan memulai login lagi.

### 3. Menu apps di navbar solution

`GET /api/v1/auth/apps` menerima token user dari solution mana pun. Endpoint ini mengembalikan solution yang
bisa dibuka untuk company aktif token:

```bash
curl "$PLATFORM/api/v1/auth/apps" -H "Authorization: Bearer $TOKEN"
```

```json
{
  "status": "success",
  "data": [
    {
      "id": "954dcaaf-…",
      "code": "kasir-pintar",
      "name": "Kasir Pintar",
      "description": "Aplikasi kasir (POS) untuk toko retail.",
      "icon_url": null,
      "launch_url": "https://kasir.contoh.com/",
      "is_current": true
    },
    {
      "id": "1b2c…",
      "code": "platform-console",
      "name": "Platform Console",
      "description": null,
      "icon_url": null,
      "launch_url": "https://console.contoh.com/",
      "is_current": false
    }
  ]
}
```

Tampilkan sebagai grid. Untuk item selain `is_current`, buka `launch_url` dengan `?company_id=<cid>` agar
solution tujuan masuk ke company yang sama. Token tanpa company aktif mendapat daftar kosong, kecuali
platform admin.

::note
Selama syarat subscription nonaktif, daftar berisi semua solution aktif yang punya URL aplikasi. Saat syarat
itu diaktifkan, daftar hanya berisi solution yang di-subscribe company.
::

## Logout

| Logout dari | Efek |
|---|---|
| Console | Sesi console dicabut, **beserta semua sesi solution yang dibuat lewat SSO dari sesi itu**. Access token solution langsung ditolak (`401`). |
| Solution | Hanya sesi solution itu yang dicabut. Sesi console dan solution lain tetap aktif, jadi klik launcher berikutnya langsung masuk lagi. |

Solution yang menerima `401` cukup memanggil `startLogin()`. Bila sesi console masih ada, user langsung
masuk lagi tanpa mengetik password.

## Ringkasan endpoint

| Endpoint | Auth | Keterangan |
|---|---|---|
| `POST /api/v1/auth/authorize` | Token user **sesi console** | Menerbitkan kode. Dipanggil halaman `/authorize` console, bukan oleh solution. Token solution lain → `403`. |
| `POST /api/v1/auth/token-exchange` | Publik (kode + PKCE) | Menukar kode menjadi sesi solution |
| `GET /api/v1/auth/apps` | Token user solution mana pun | Daftar launcher / menu apps |
