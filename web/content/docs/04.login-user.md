---
title: Login user
description: Alur login, memilih company aktif, refresh, dan logout dari frontend solution.
---

Alur ini dipakai aplikasi yang bertindak **atas nama user** (frontend web/mobile solution, atau backend
yang meneruskan login user).

```text
1. POST /auth/login           → token tanpa cid
2. GET  /auth/companies       → company yang bisa dipilih
3. POST /auth/switch-company  → token baru dengan cid
4. GET  /auth/me              → data user & sesi
   ... panggil API dengan Bearer token ...
5. POST /auth/refresh         → pasangan token baru
6. POST /auth/logout          → sesi dicabut
```

User dibuat oleh platform admin (`POST /api/v1/users` atau console **Platform → Users**). Platform belum
menyediakan registrasi mandiri.

## 1. Login

```bash
curl -X POST "$PLATFORM/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"email": "budi@acme.co.id", "password": "rahasia123", "solution": "hris"}'
```

`solution` adalah `code` solution Anda; nilainya menjadi `aud` token.

Respons `200`:

```json
{
  "status": "success",
  "status_code": 200,
  "message": "logged in",
  "data": {
    "access_token": "eyJhbGciOiJSUzI1NiIs...",
    "token_type": "Bearer",
    "expires_in": 900,
    "access_token_expires_at": "2026-10-30T08:15:00Z",
    "refresh_token": "kC7m2...",
    "refresh_token_expires_at": "2026-11-29T08:00:00Z",
    "session_id": "e51c9b3a-...",
    "company_id": null
  }
}
```

| Kondisi | Respons |
|---|---|
| Email tidak ada / password salah | `401` — pesan sama untuk keduanya |
| User `inactive` / `suspended` | `403` |
| Solution tidak ada / `inactive` | `422` |
| Field kosong | `422` dengan error per field |

Token hasil login **belum punya company aktif** (`company_id: null`, tanpa claim `cid`). Endpoint
per-company akan menolaknya dengan `403` — *"Pilih company aktif terlebih dahulu."*

## 2. Daftar company yang bisa dipilih

```bash
curl "$PLATFORM/api/v1/auth/companies" -H "Authorization: Bearer $TOKEN"
```

```json
{
  "data": [
    { "id": "7d2e4c10-...", "name": "PT Acme", "slug": "acme", "status": "active", "is_active": false },
    { "id": "1a9f8b22-...", "name": "PT Beta", "slug": "beta", "status": "active", "is_active": false }
  ]
}
```

Berisi company `active` tempat user menjadi member `active`. `is_active` menandai company aktif token saat
ini.

- **Satu company** → langsung lakukan switch tanpa menampilkan pilihan.
- **Beberapa company** → tampilkan pemilih (mis. setelah login, dan di header aplikasi).
- **Kosong** → user belum menjadi member di mana pun. Tampilkan pesan, atau biarkan user membuat company
  (`POST /api/v1/companies`, user pembuat otomatis menjadi member aktif).

## 3. Pilih company aktif

```bash
curl -X POST "$PLATFORM/api/v1/auth/switch-company" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"company_id": "7d2e4c10-..."}'
```

Respons sama dengan login, dengan `company_id` terisi dan token berisi claim `cid`.

::warning
Switch company menerbitkan **access token dan refresh token baru**. Refresh token lama langsung tidak
berlaku — ganti keduanya di storage.
::

Company yang tidak aktif atau bukan tempat user menjadi member aktif → `403` — *"Company ini tidak bisa
dipilih: ..."*.

Switch bisa dilakukan kapan saja untuk berpindah company tanpa login ulang.

## 4. User & sesi saat ini

```bash
curl "$PLATFORM/api/v1/auth/me" -H "Authorization: Bearer $TOKEN"
```

```json
{
  "data": {
    "user": {
      "id": "0b9a1f6e-...",
      "email": "budi@acme.co.id",
      "name": "Budi",
      "status": "active",
      "is_platform_admin": false,
      "has_password": true,
      "created_at": "...",
      "updated_at": "..."
    },
    "session": {
      "id": "e51c9b3a-...",
      "solution": { "id": "6f1c0a52-...", "code": "hris", "name": "HRIS" },
      "company_id": "7d2e4c10-...",
      "expires_at": "2026-11-29T08:00:00Z",
      "created_at": "2026-10-30T08:00:00Z"
    }
  }
}
```

User bisa mengubah nama / password sendiri lewat `PATCH /api/v1/users/me`
(`{"name": "...", "password": "...", "current_password": "..."}`).

## 5. Refresh token

```bash
curl -X POST "$PLATFORM/api/v1/auth/refresh" \
  -H "Content-Type: application/json" \
  -d '{"refresh_token": "kC7m2..."}'
```

Endpoint publik (tanpa Bearer). Mengembalikan pasangan token baru dengan company aktif yang sama.
**Refresh token di-rotate**: setiap refresh token hanya bisa dipakai sekali.

Rekomendasi:

- Refresh saat access token hampir habis (mis. 60 detik sebelum `access_token_expires_at`), atau saat
  menerima `401`.
- Pastikan hanya **satu** refresh berjalan bersamaan (antre request lain sampai selesai). Dua refresh
  paralel dengan token yang sama akan membuat salah satunya gagal.
- `401` dari refresh → sesi berakhir, arahkan ke login.

## 6. Logout

```bash
curl -X POST "$PLATFORM/api/v1/auth/logout" -H "Authorization: Bearer $TOKEN"
```

Mencabut sesi saat ini. Access token dan refresh token sesi ini langsung ditolak platform (walau `exp`
belum lewat). Hapus token dari storage di sisi klien.

## Penanganan 401 / 403 di frontend

| Respons | Penyebab umum | Tindakan |
|---|---|---|
| `401` | Token kedaluwarsa, sesi logout/direvoke, user dinonaktifkan | Coba refresh sekali; gagal → login |
| `403` pada endpoint per-company, token tanpa `cid` | Belum memilih company | Arahkan ke pemilihan company |
| `403` pada endpoint per-company, token ber-`cid` | Member dikeluarkan, atau `companyId` di path berbeda dari `cid` | Muat ulang `/auth/companies`, minta pilih ulang |
| `403` lain | Bukan platform admin, dsb. | Tampilkan pesan dari `errors` |

`error_code` di respons error adalah kode umum (`ERR_UNAUTHORIZED`, `ERR_FORBIDDEN`, ...); penyebab detail
hanya ada di pesan `errors`. Lihat [Error](/docs/errors).
