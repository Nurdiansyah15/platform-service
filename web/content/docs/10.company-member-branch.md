## Aturan akses

Semua endpoint di bawah `/companies/{companyId}/...` memeriksa akses dengan aturan yang sama:

| Pemanggil | Boleh mengakses company |
|---|---|
| Platform admin | Semua company |
| Token service | Semua company (selama gate subscription nonaktif), sesuai scope |
| Token user lain | Hanya company aktif token (`cid` = `companyId`) **dan** user member `active` |

- Token user tanpa `cid` → `403` (*"Pilih company aktif terlebih dahulu."*).
- Resource yang diakses lewat ID-nya sendiri (mis. `/branches/{branchId}`, `/role-assignments/{id}`) milik
  company yang tidak boleh diakses dilaporkan **`404`**, bukan `403`, agar keberadaan data company lain
  tidak bocor.
- Endpoint **baca** terbuka untuk semua member aktif. Endpoint **tulis** dengan token user butuh
  [permission platform](/docs/arsitektur-integrasi#permission-platform): `company.manage` (ubah company), `member.manage` (buat user, kelola
  anggota), `branch.manage` (kelola cabang; boleh di level cabang untuk ubah/hapus cabang itu). Tanpa izin →
  `403`. Pembuat company otomatis memegang role `company_admin` yang berisi semua permission platform.
- Token service tidak dicek permission platform. Pakai hanya untuk pekerjaan sistem; untuk aksi yang dipicu
  user, teruskan token user (lihat [Arsitektur integrasi](/docs/arsitektur-integrasi#_4-mengubah-data-organisasi)).

## Company

| Method & path | Siapa | Keterangan |
|---|---|---|
| `POST /api/v1/companies` | Token user | Membuat company. Pembuat (bukan admin) otomatis menjadi member `active` |
| `GET /api/v1/companies` | Token user | Company tempat user menjadi member `active` (admin: semua) |
| `GET /api/v1/companies/{companyId}` | User / service `users:read` | Detail |
| `PATCH /api/v1/companies/{companyId}` | User / service `org:write` | Ubah `name`, `slug`. `status` hanya platform admin |
| `GET /api/v1/companies/{companyId}/summary` | User / service `users:read` | Jumlah member, branch, role custom, assignment |

Membuat company:

```bash
curl -X POST "$PLATFORM/api/v1/companies" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "PT Acme Indonesia", "slug": "acme"}'
```

```json
{
  "data": {
    "id": "7d2e4c10-...",
    "name": "PT Acme Indonesia",
    "slug": "acme",
    "status": "active",
    "created_at": "...",
    "updated_at": "...",
    "member_count": 0
  }
}
```

`slug`: huruf kecil, angka, dan `-` (maks 100), unik → `409` bila sudah dipakai. Setelah membuat company,
lakukan [switch company](/docs/login-user) untuk memakainya.

Status company: `active`, `suspended`, `closed`. Hanya company `active` yang bisa dipilih saat switch.

## Member

| Method & path | Scope service | Keterangan |
|---|---|---|
| `GET /api/v1/companies/{companyId}/members` | `users:read` | List; filter `status`, `search`, pagination |
| `GET /api/v1/companies/{companyId}/members/{userId}` | `users:read` | Detail |
| `POST /api/v1/companies/{companyId}/members` | `users:write` | Tambah user terdaftar |
| `PATCH /api/v1/companies/{companyId}/members/{userId}` | `users:write` | Ubah status |
| `DELETE /api/v1/companies/{companyId}/members/{userId}` | `users:write` | Keluarkan member |
| `GET /api/v1/companies/{companyId}/member-candidates?search=` | `users:write` | Cari user untuk ditambahkan (min. 3 karakter) |

### Menambah member

User harus **sudah terdaftar** di platform. Untuk user baru, pakai
[membuat akun user dari company](#membuat-akun-user-dari-company). Isi salah satu, `user_id` atau `email`:

```bash
curl -X POST "$PLATFORM/api/v1/companies/$COMPANY_ID/members" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email": "siti@acme.co.id", "status": "active"}'
```

```json
{
  "data": {
    "company_id": "7d2e4c10-...",
    "user_id": "3c4d...",
    "email": "siti@acme.co.id",
    "name": "Siti",
    "status": "active",
    "joined_at": "2026-10-30T08:30:00Z",
    "role_count": 0
  }
}
```

- `status`: `active` (default) atau `invited`. Member `invited` belum punya akses.
- Sudah member `active`/`invited` → `409`. Member `inactive` akan diaktifkan kembali.
- Email tidak terdaftar → `422`.

### Membuat akun user dari company

Buat akun baru (ber-password) sekaligus menjadikannya anggota. Token user butuh `member.manage`; token
service butuh scope `users:write`.

```bash
curl -X POST "$PLATFORM/api/v1/companies/$COMPANY_ID/users" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Rudi Hartono", "email": "rudi@acme.co.id", "password": "Sementara#2026", "status": "active"}'
```

- Respons `201` sama dengan menambah member (`user_id`, `email`, `name`, `status`, `joined_at`).
- Email sudah terdaftar → `409`; tambahkan sebagai member dengan `POST /members`.
- Password minimal 8 karakter. User bisa langsung login dan menggantinya lewat `PATCH /users/me`.

### Status member

| Status | Arti |
|---|---|
| `invited` | Diundang, belum punya akses |
| `active` | Punya akses; satu-satunya status yang lolos aturan akses & authz |
| `inactive` | Dikeluarkan |

Mengeluarkan member (`DELETE`, atau `PATCH` ke `inactive`) **menghapus semua role assignment** user di
company itu. Bila diaktifkan kembali, role harus di-assign ulang.

Daftar user yang belum ada di company, untuk form "tambah member":

```bash
curl "$PLATFORM/api/v1/companies/$COMPANY_ID/member-candidates?search=sit" \
  -H "Authorization: Bearer $TOKEN"
# → [{ "id": "...", "name": "Siti", "email": "siti@acme.co.id" }]
```

## Branch

| Method & path | Scope service | Keterangan |
|---|---|---|
| `GET /api/v1/companies/{companyId}/branches` | `org:read` | List; filter `status`, `search`, pagination |
| `POST /api/v1/companies/{companyId}/branches` | `org:write` | Buat branch |
| `PATCH /api/v1/branches/{branchId}` | `org:write` | Ubah `name`, `code`, `status` |
| `DELETE /api/v1/branches/{branchId}` | `org:write` | Hapus (soft delete) |

```bash
curl -X POST "$PLATFORM/api/v1/companies/$COMPANY_ID/branches" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Cabang Bandung", "code": "BDG", "status": "active"}'
```

```json
{
  "data": {
    "id": "a81e...",
    "company_id": "7d2e4c10-...",
    "name": "Cabang Bandung",
    "code": "BDG",
    "status": "active",
    "created_at": "...",
    "updated_at": "..."
  }
}
```

- `code` unik per company (`409` bila dobel); boleh huruf, angka, `.`, `_`, `-`.
- `status`: `active` / `inactive`.
- Menghapus branch ikut menghapus role assignment yang ber-scope branch tersebut.

## Data user

Token service belum punya endpoint untuk membuat atau membaca user secara langsung. Data user yang
relevan (nama, email) didapat dari daftar member company. Pembuatan user dilakukan platform admin
(`POST /api/v1/users`).
