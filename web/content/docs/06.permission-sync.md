---
title: Sinkronisasi permission
description: Mendaftarkan katalog permission solution ke platform, idealnya otomatis di setiap deploy.
---

Permission didefinisikan oleh **solution**, bukan oleh platform. Solution mengirim seluruh katalognya ke
platform; role kemudian disusun dari permission tersebut.

Disarankan menjalankan sync **otomatis saat deploy / startup** backend solution, dengan katalog yang
disimpan di kode solution.

## Format permission

- `code`: huruf kecil, segmen dipisah `.` atau `:` — mis. `employee.read`, `payroll.run`, `leave:approve`.
  Pola: `^[a-z][a-z0-9_-]*([.:][a-z0-9_-]+)*$`, maks 150 karakter.
- `name`: label untuk UI (maks 255).
- `description`: opsional.

Saran penamaan: `<resource>.<aksi>` (`employee.create`, `employee.read`, `employee.update`, `employee.delete`).

## Endpoint

`PUT /api/v1/solutions/{solutionId}/permissions/sync`

Dipanggil dengan token service ber-scope `catalog:sync` **milik solution tersebut**, atau token user
platform admin.

```bash
curl -X PUT "$PLATFORM/api/v1/solutions/$SOLUTION_ID/permissions/sync" \
  -H "Authorization: Bearer $SERVICE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "version": "2026.10.30-1",
    "permissions": [
      { "code": "employee.read",   "name": "Lihat karyawan" },
      { "code": "employee.create", "name": "Tambah karyawan" },
      { "code": "payroll.run",     "name": "Jalankan payroll", "description": "Proses penggajian bulanan" }
    ]
  }'
```

Respons `200`:

```json
{
  "data": {
    "version": "2026.10.30-1",
    "changed": true,
    "created": 3,
    "updated": 0,
    "reactivated": 0,
    "deprecated": 0,
    "unchanged": 0
  }
}
```

## Perilaku

| Situasi | Hasil |
|---|---|
| `version` sama dengan versi tersimpan | Tidak ada perubahan, `changed: false`. Aman dipanggil di setiap startup. |
| Code baru | Dibuat (`created`) |
| Code ada, nama/deskripsi berubah | Diperbarui (`updated`) |
| Code **tidak lagi** ada di katalog | Menjadi `deprecated` — tidak dihapus |
| Code deprecated muncul lagi | Aktif kembali (`reactivated`) |

- Katalog bersifat **replace-all**: kirim seluruh permission setiap kali, bukan hanya yang berubah.
- `version` wajib (maks 50 karakter). Gunakan sesuatu yang berubah setiap katalog berubah, mis. hash isi
  katalog, versi aplikasi, atau tanggal + nomor.
- Sync dikunci per solution sehingga beberapa instance yang deploy bersamaan tidak bentrok.

### Permission deprecated

- Tidak bisa **ditambahkan** ke role.
- Yang sudah terpasang di role **tetap berlaku** dalam authz check, agar role lama tidak rusak saat
  katalog berubah. Bersihkan role secara manual bila permission memang sudah tidak dipakai.

## Melihat katalog

`GET /api/v1/solutions/{solutionId}/permissions` — bisa dipanggil token apa pun.

Query: `status` (`active` / `deprecated`), `search`, dan pagination (`page`, `limit`, `sort_by`, `sort_type`).

```json
{
  "data": [
    {
      "id": "c0f1...",
      "solution_id": "6f1c0a52-...",
      "code": "employee.read",
      "name": "Lihat karyawan",
      "description": null,
      "status": "active",
      "created_at": "...",
      "updated_at": "..."
    }
  ],
  "meta": { "current_page": 1, "per_page": 10, "total": 3, "total_pages": 1 }
}
```

`permission_catalog_version` pada [`GET /solutions/{id}`](/docs/onboarding-solution) menunjukkan versi
terakhir yang tersinkron.

## Error umum

| Status | Penyebab |
|---|---|
| `403` | Token service milik solution lain, scope `catalog:sync` tidak ada, atau user bukan platform admin |
| `404` | Solution tidak ditemukan |
| `422` | `version` kosong, `code` tidak sesuai pola, `name` kosong, atau `code` dobel di katalog |
