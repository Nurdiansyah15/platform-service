## Checklist integrasi

**Persiapan (platform admin)**

- [ ] Solution dibuat, `code` dan `id` dicatat — [Onboarding](/docs/onboarding-solution)
- [ ] Solution client dibuat per environment, secret disimpan di secret manager
- [ ] User awal dibuat (`POST /api/v1/users`) dan dimasukkan ke company

**Backend solution**

- [ ] Ambil token service via `POST /oauth/token`, cache sampai hampir habis — [Token service](/docs/service-token)
- [ ] Sync katalog permission otomatis saat deploy — [Sinkronisasi permission](/docs/permission-sync)
- [ ] Verifikasi token user dengan JWKS (`iss`, `aud` = code solution, `typ=user`, `exp`) — [Token](/docs/token)
- [ ] Tegakkan izin dengan `authz/check` / `check-batch` di setiap aksi penting — [Authz](/docs/authz)
- [ ] Ubah data organisasi atas nama user dengan **meneruskan token user**; token service hanya untuk pekerjaan sistem — [Arsitektur integrasi](/docs/arsitektur-integrasi)
- [ ] Data bisnis menyimpan `company_id` / `branch_id` / `user_id` dari platform, bukan salinan tabel user/role
- [ ] Tangani `401`/`403`/`404`/`409`/`422` sesuai [Error](/docs/errors)

**Frontend solution**

- [ ] Masuk lewat SSO console (`/authorize` → `/auth/token-exchange`), atau login dengan `solution` = code solution — [SSO dari console](/docs/sso-console), [Login user](/docs/login-user)
- [ ] Sembunyikan aksi administrasi company bila user tidak punya permission platform (`effective-permissions` solution console)
- [ ] Menu apps di navbar dari `GET /auth/apps` — [SSO dari console](/docs/sso-console#_3-menu-apps-di-navbar-solution)
- [ ] Pemilihan company (`/auth/companies` → `/auth/switch-company`), simpan token baru
- [ ] Refresh token tunggal (satu refresh berjalan bersamaan), ganti refresh token setiap kali
- [ ] Menu/UI berdasarkan `effective-permissions`
- [ ] Logout memanggil `/auth/logout` lalu menghapus token

**Role**

- [ ] Role global standar disiapkan platform admin, atau UI role custom di solution — [Role](/docs/role)
- [ ] UI assign role memakai `GET /companies/{cid}/solutions/{sid}/roles` untuk daftar role

## Roadmap

Fitur berikut sudah ada di platform tetapi **belum diaktifkan**. Rencanakan integrasi agar tidak perlu
dirombak saat diaktifkan.

### Syarat subscription (gate)

Saat diaktifkan kembali:

- `GET /auth/companies` hanya menampilkan company yang berlangganan solution Anda (`trialing` / `active`);
  `switch-company` ke company lain ditolak `403`.
- Token service hanya bisa mengakses company yang berlangganan solution-nya (`403` untuk yang lain).
- Membuat role custom dan assign role butuh subscription aktif (`403`).
- `authz/check` mengembalikan `allowed: false` untuk company tanpa subscription aktif.

**Persiapan:** tangani `403` di alur pemilihan company dengan pesan yang jelas ("company belum berlangganan"),
dan jangan mengasumsikan semua company selalu bisa dipilih.

### Entitlement & usage

Batas plan (mis. jumlah karyawan, fitur premium) akan dibaca dari
`GET /companies/{cid}/solutions/{sid}/entitlements` dan pemakaian dilaporkan lewat usage API. Belum perlu
diintegrasikan.

### Webhook

Platform akan mengirim event (mis. member ditambahkan/dikeluarkan, role assignment berubah, permission
role berubah) ke endpoint webhook solution. Sampai aktif, gunakan polling / cek langsung ke API bila butuh
data terbaru.
