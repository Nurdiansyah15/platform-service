title: Token
description: Isi token user dan token service, cara memverifikasinya, dan apa yang divalidasi platform.
---

Platform menerbitkan **JWT RS256**. Semua request terproteksi memakai header:

```http
Authorization: Bearer <access_token>
```

## Token user

Didapat dari [login](/docs/login-user). Mewakili satu user di satu solution, dengan satu company aktif.

| Claim | Isi |
|---|---|
| `iss` | URL platform (`ISSUER_URL`) |
| `sub` | `users.id` |
| `aud` | `solutions.code` — solution tempat user login |
| `cid` | ID company aktif. **Tidak ada** sebelum user memilih company |
| `sid` | ID sesi login |
| `typ` | `user` |
| `iat`, `exp`, `jti` | Standar JWT |

Contoh payload:

```json
{
  "iss": "https://platform.example.com",
  "sub": "0b9a1f6e-...",
  "aud": "hris",
  "cid": "7d2e4c10-...",
  "sid": "e51c9b3a-...",
  "typ": "user",
  "iat": 1793347200,
  "exp": 1793348100,
  "jti": "9f8e..."
}
```

## Token service

Didapat dari [client credentials](/docs/service-token). Mewakili backend solution.

| Claim | Isi |
|---|---|
| `iss` | URL platform |
| `sub` | `client_id` solution client |
| `aud` | `platform` |
| `sol` | `solutions.id` |
| `scope` | Daftar scope, dipisah spasi |
| `typ` | `service` |
| `iat`, `exp`, `jti` | Standar JWT |

::note
Permission, role, dan entitlement **tidak** dimasukkan ke token. Cek permission selalu lewat
[authz check](/docs/authz).
::

## Masa berlaku

| Token | Default | Konfigurasi |
|---|---|---|
| Access token (user & service) | 15 menit | `ACCESS_TOKEN_TTL` |
| Refresh token (user) | 30 hari | `REFRESH_TOKEN_TTL` |

Pakai `expires_in` / `access_token_expires_at` dari respons, jangan mengasumsikan nilai default.

## Verifikasi di sisi solution

Backend solution boleh memverifikasi token user secara lokal (mis. untuk mengambil `sub` dan `cid`) dengan
public key dari JWKS:

```bash
curl "$PLATFORM/api/v1/.well-known/jwks.json"
```

```json
{
  "keys": [
    { "kty": "RSA", "use": "sig", "alg": "RS256", "kid": "<kid>", "n": "...", "e": "AQAB" }
  ]
}
```

Aturan verifikasi:

1. `alg` harus `RS256`; pilih key berdasarkan `kid` di header JWT.
2. `iss` sama dengan URL platform.
3. `aud` sama dengan `code` solution Anda (token user) — tolak token untuk solution lain.
4. `typ` sesuai yang diharapkan (`user`).
5. `exp` belum lewat.

Cache JWKS (mis. 10–60 menit) dan ambil ulang bila menemukan `kid` yang belum dikenal. JWKS bisa
berisi lebih dari satu key saat rotasi.

::warning
Verifikasi lokal hanya membuktikan token **pernah** sah. Logout, user dinonaktifkan, atau member
dikeluarkan tidak terlihat dari token. Untuk keputusan akses, panggil API platform (mis.
[`/authz/check`](/docs/authz)) — platform selalu memvalidasi ulang ke database.
::

## Yang divalidasi platform di setiap request

**Token user:**

- Sesi masih aktif (belum logout / kedaluwarsa / direvoke).
- User dan solution masih `active`.
- `cid` di token sama dengan company aktif sesi.
- Status platform admin diambil dari database, bukan dari token.

**Token service:**

- Client dan solution masih `active`; `sol` cocok dengan solution client.
- Scope di-*intersect* dengan scope client saat ini — scope yang sudah dicabut langsung tidak berlaku.

## Guard per endpoint

| Guard | Arti | Gagal |
|---|---|---|
| Tanpa token / token tidak valid | — | `401` |
| User saja | Endpoint `/auth/*`, `GET/POST /companies`, `/users/me` | `403` untuk token service |
| User atau service + scope | Hampir semua endpoint per-company | `403` bila scope kurang |
| Platform admin | Kelola solution, client, user, role global | `403` |
