Platform ini adalah pusat identitas, organisasi, dan hak akses untuk semua **solution** (aplikasi yang
memakai platform). Solution tidak menyimpan user, company, atau role sendiri — semuanya dibaca dari
platform lewat API ini.

Panduan ini ditujukan untuk tim yang membangun solution dan ingin melakukan **integrasi pertama**:
login user, memilih company, mengelola member/role, dan mengecek permission.

## Status fitur

Platform dirilis bertahap. Saat ini yang aktif hanya bagian **auth & authz**.

| Area | Status | Keterangan |
|---|---|---|
| Login user, refresh, logout, pilih company | ✅ Aktif | [Login user](/docs/login-user) |
| SSO console → solution & menu apps | ✅ Aktif | [SSO dari console](/docs/sso-console) |
| Token service (client credentials) & JWKS | ✅ Aktif | [Token](/docs/token), [Token service](/docs/service-token) |
| User, company, member, branch | ✅ Aktif | [Company, member & branch](/docs/company-member-branch) |
| Katalog permission (sync dari solution) | ✅ Aktif | [Sinkronisasi permission](/docs/permission-sync) |
| Role global & role custom company | ✅ Aktif | [Role](/docs/role) |
| Role assignment & authz check | ✅ Aktif | [Authz](/docs/authz) |
| Subscription, plan, add-on | ⏸ Belum dipakai | Endpoint ada, tapi tidak membatasi akses |
| Entitlement & usage | ⏸ Belum dipakai | Jangan diintegrasikan dulu |
| Webhook ke solution | ⏸ Belum dipakai | Pengiriman berbasis subscription, jadi belum bisa diandalkan |

::note
**Syarat subscription sedang dinonaktifkan.** Setiap company `active` boleh memakai setiap solution
`active` tanpa harus berlangganan. Artinya: user bisa memilih company mana pun tempat dia menjadi member,
token service bisa mengakses company mana pun, dan role bisa di-assign tanpa subscription.
Saat syarat ini diaktifkan lagi, company yang belum subscribe akan ditolak — lihat
[Checklist & roadmap](/docs/checklist-roadmap).
::

## Konsep utama

| Istilah | Arti |
|---|---|
| **Solution** | Aplikasi yang terintegrasi dengan platform. Punya `code` unik (mis. `hris`), yang menjadi `aud` token user. |
| **Solution client** | Kredensial mesin-ke-mesin (`client_id` + `client_secret`) milik satu solution, dipakai backend solution untuk mendapat token service. |
| **User** | Akun orang. Satu user bisa login ke banyak solution dan menjadi member di banyak company. |
| **Company** | Entitas tertinggi (pelanggan/tenant). Status `active`, `suspended`, atau `closed`. |
| **Member** | Keanggotaan user di company. Status `invited`, `active`, atau `inactive`. Hanya member `active` yang punya akses. |
| **Branch** | Cabang di bawah company. Bisa menjadi scope role assignment. |
| **Permission** | Hak akses milik satu solution (mis. `invoice.create`). Didaftarkan oleh solution lewat sync katalog. |
| **Role** | Kumpulan permission dalam satu solution. **Global** (dibuat platform, berlaku di semua company) atau **custom** (milik satu company). |
| **Role assignment** | Pemberian role ke member pada scope `company` atau `branch`. |

**Hierarki scope:** assignment di level company berlaku untuk company itu **dan** semua branch di bawahnya.
Assignment di level branch hanya berlaku di branch itu.

## Dua jenis pemanggil

| | Token user | Token service |
|---|---|---|
| Dipakai oleh | Frontend / aplikasi atas nama user | Backend solution |
| Didapat dari | `POST /api/v1/auth/login` | `POST /api/v1/oauth/token` |
| Konteks company | Satu company aktif (`cid`) | Semua company (selama gate subscription nonaktif) |
| Batasan | Hanya company aktif & dirinya sendiri | Scope client + data solution miliknya |

Detail: [Token](/docs/token).

## Format respons

Semua endpoint berada di bawah `/api/v1`. Respons sukses memakai envelope:

```json
{
  "status": "success",
  "status_code": 200,
  "message": "logged in",
  "data": { "...": "..." },
  "meta": null
}
```

Endpoint list mengisi `meta`:

```json
"meta": { "current_page": 1, "per_page": 10, "total": 42, "total_pages": 5 }
```

Query pagination list: `page`, `limit`, `sort_by`, `sort_type` (`asc` / `desc`), biasanya ditambah `search`
dan `status`.

Respons error:

```json
{
  "status": "error",
  "status_code": 403,
  "error_code": "ERR_FORBIDDEN",
  "errors": "Anda tidak memiliki akses ke company ini."
}
```

Pesan di `errors` diterjemahkan sesuai `Accept-Language` (`id` / `en`) atau query `?lang=`. Detail di
[Error](/docs/errors).

**Pengecualian (tanpa envelope):** `GET /api/v1/.well-known/jwks.json` dan `POST /api/v1/oauth/token`
mengikuti format standar (RFC 7517 / RFC 6749) agar bisa dibaca library pihak ketiga.

## Contoh di dokumentasi ini

Semua contoh memakai `curl` dengan variabel:

```bash
export PLATFORM=http://localhost:8080      # base URL platform
export TOKEN=eyJhbGciOi...                 # access token (user atau service)
```

Referensi field lengkap ada di [API Reference](/docs/api-reference).
