---
title: Sinkronisasi permission
description: Mendaftarkan katalog permission solution ke platform, idealnya otomatis di setiap deploy.
---

Permission biasanya didefinisikan oleh **solution**: solution mengirim seluruh katalognya ke platform, lalu
role disusun dari permission tersebut. Platform admin juga bisa menambah permission **manual** dari
console (lihat [Permission manual](#permission-manual)). Setiap permission punya `source`: `sync` atau
`manual`.

Disarankan menjalankan sync **otomatis saat deploy / startup** backend solution, dengan katalog yang
disimpan di kode solution.

## Format permission

- `code`: huruf kecil, segmen dipisah `.` atau `:` — mis. `employee.read`, `payroll.run`, `leave:approve`.
  Pola: `^[a-z][a-z0-9_-]*([.:][a-z0-9_-]+)*$`, maks 150 karakter.
- `name`: label untuk UI (maks 255).
- `description`: opsional.
- `group`: opsional — code grup dari `groups` (lihat di bawah).

Permission tidak menyimpan scope. Di level apa sebuah permission berlaku (seluruh company, cabang, atau
scope custom) ditentukan saat permission dipasang ke **role** — lihat [Role](/docs/role#permission-role).

Saran penamaan: `<resource>.<aksi>` (`employee.create`, `employee.read`, `employee.update`, `employee.delete`).

## Grup & scope custom (opsional)

Katalog minimal cukup berisi `version` + `permissions`. Dua bagian berikut boleh ditambahkan kapan saja,
tanpa mengubah perilaku permission yang sudah ada:

**`groups`** — mengelompokkan permission untuk UI. Saat admin menyusun role di console, permission
tampil per grup dengan nama dan deskripsinya, bukan code mentah. Urutan array = urutan tampil
(di antara grup seinduk). Permission tanpa `group` dikelompokkan berdasarkan prefix code sebelum `.`
seperti biasa.

| Field | Aturan |
|---|---|
| `code` | huruf kecil/angka/`_`/`-`, diawali huruf, maks 100 |
| `name` | wajib, maks 255 |
| `description` | opsional |
| `parent` | opsional — code grup induk di `groups` yang sama (boleh ditulis sebelum atau sesudah induknya) |

Grup boleh bertingkat **maksimal 3 level**, mis. modul › menu › submenu, tanpa siklus. Permission
boleh dipasang di grup level mana pun. Satu permission hanya masuk **satu** grup: pilih grup modul
pemilik datanya / endpoint-nya (mis. `payroll.read` di grup Payroll walaupun tab gajinya tampil di menu
Data Karyawan — layar itu cukup mengecek `payroll.read`).

**`scope_types`** — scope sendiri di luar `company` dan `branch` (selalu tersedia), mis. `department`,
`project`, `warehouse`. Scope ini datanya milik solution: platform tidak menyimpan daftar departemen,
hanya jenis scope-nya. Permission role bisa dipasang ber-scope `department`, lalu saat role diberikan ke
anggota diisi departemen mana (lihat [Authz](/docs/authz#nilai-scope)).

| Field | Aturan |
|---|---|
| `code` | huruf kecil/angka/`_`, diawali huruf, maks 30; **bukan** `company` / `branch` |
| `name` | wajib — nama tampilan, mis. "Departemen" |
| `description` | opsional |
| `parent` | `company` (default) atau `branch` — scope ini bagian dari apa. Permission ber-scope cabang ikut mencakup scope custom ber-parent `branch` di cabang itu. |

## Endpoint

`PUT /api/v1/solutions/{solutionId}/permissions/sync`

Dipanggil dengan token service ber-scope `catalog:sync` **milik solution tersebut**, atau token user
platform admin.

```bash
curl -X PUT "$PLATFORM/api/v1/solutions/$SOLUTION_ID/permissions/sync" \
  -H "Authorization: Bearer $SERVICE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "version": "2026.10.30-1",
    "permissions": [
      { "code": "employee.read",   "name": "Lihat karyawan" },
      { "code": "employee.create", "name": "Tambah karyawan" },
      { "code": "payroll.run",     "name": "Jalankan payroll", "description": "Proses penggajian bulanan" }
    ]
  }'
```

Dengan grup dan scope custom:

```json
{
  "version": "2026.11.24-1",
  "scope_types": [
    { "code": "department", "name": "Departemen", "parent": "branch" }
  ],
  "groups": [
    { "code": "hr",       "name": "Kepegawaian" },
    { "code": "employee", "name": "Data Karyawan", "parent": "hr" },
    { "code": "payroll",  "name": "Payroll", "description": "Penggajian" }
  ],
  "permissions": [
    { "code": "employee.read", "name": "Lihat karyawan", "group": "employee" },
    { "code": "leave.approve", "name": "Setujui cuti", "group": "employee" },
    { "code": "payroll.run",   "name": "Jalankan payroll", "group": "payroll" }
  ]
}
```

Respons `200`:

```json
{
  "data": {
    "version": "2026.10.30-1",
    "changed": true,
    "created": 3,
    "updated": 0,
    "reactivated": 0,
    "deprecated": 0,
    "unchanged": 0,
    "groups":      { "created": 0, "updated": 0, "reactivated": 0, "deprecated": 0, "unchanged": 0 },
    "scope_types": { "created": 0, "updated": 0, "reactivated": 0, "deprecated": 0, "unchanged": 0 }
  }
}
```

Counter di level atas untuk permission; `groups` dan `scope_types` punya counter sendiri.

## Perilaku

| Situasi | Hasil |
|---|---|
| `version` sama dengan versi tersimpan | Tidak ada perubahan, `changed: false`. Aman dipanggil di setiap startup. |
| Code baru | Dibuat (`created`) |
| Code ada, nama/deskripsi berubah | Diperbarui (`updated`) |
| Code **tidak lagi** ada di katalog | Menjadi `deprecated` — tidak dihapus |
| Code deprecated muncul lagi | Aktif kembali (`reactivated`) |
| Grup / scope type hilang dari katalog | Menjadi `deprecated`. Permission yang tidak lagi menyebut grup lepas dari grupnya. |
| Permission / grup / scope type `manual` tidak ada di katalog | Tidak berubah — sync hanya mengelola entri `source: sync` |
| Katalog memuat code permission, grup, atau scope type `manual` | Seluruh sync ditolak `409`, tidak ada yang diubah |

- Katalog bersifat **replace-all**: kirim seluruh permission (dan grup / scope type bila dipakai) setiap
  kali, bukan hanya yang berubah.
- `version` wajib (maks 50 karakter). Gunakan sesuatu yang berubah setiap katalog berubah, mis. hash isi
  katalog, versi aplikasi, atau tanggal + nomor.
- Sync dikunci per solution sehingga beberapa instance yang deploy bersamaan tidak bentrok.

### Permission deprecated

- Tidak bisa **ditambahkan** ke role.
- Yang sudah terpasang di role **tetap berlaku** dalam authz check, agar role lama tidak rusak saat
  katalog berubah. Bersihkan role secara manual bila permission memang sudah tidak dipakai.

### Scope type deprecated

- Tidak bisa dipakai untuk assignment **baru** (`422`).
- Assignment lama di scope itu tetap dievaluasi dalam authz check.

## Permission manual

Untuk permission yang tidak (atau belum) dikirim backend solution, platform admin bisa mengelolanya
langsung — di console: **Solution → Permission → Tambah permission**.

| Method & path | Akses |
|---|---|
| `POST /api/v1/solutions/{solutionId}/permissions` | Platform admin |
| `GET /api/v1/permissions/{permissionId}` | Token apa pun |
| `PATCH /api/v1/permissions/{permissionId}` | Platform admin, hanya permission `manual` |

```bash
curl -X POST "$PLATFORM/api/v1/solutions/$SOLUTION_ID/permissions" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"code": "report.export", "name": "Export laporan", "group": "report"}'
```

- Body sama dengan satu entri `permissions` di sync (`code`, `name`, `description`, `group`). `group`
  harus merujuk grup yang sudah ada di katalog solution.
- `PATCH` mengubah `name`, `description`, `group`, dan `status`. Field yang tidak dikirim tidak berubah;
  `description` / `group` `""` = dikosongkan. `code` tidak bisa diubah.
- Permission tidak pernah dihapus. "Hapus" = `PATCH {"status": "deprecated"}`: tidak bisa ditambahkan ke role
  lagi, tapi yang sudah terpasang tetap berlaku. `{"status": "active"}` mengaktifkannya kembali.
- Permission `sync` read-only di platform (`PATCH` → `409`) karena akan tertimpa sync berikutnya.
- Code permission manual — termasuk yang sudah deprecated — tidak bisa dipakai di katalog sync (`409`).
  Pilih code yang tidak akan dipakai solution, mis. dengan prefix khusus.

| Status | Penyebab |
|---|---|
| `409` | Code sudah dipakai (manual atau sync), atau mengubah permission `sync` |
| `422` | Code tidak sesuai pola, `name` kosong, grup / scope tidak dikenal, `status` bukan `active`/`deprecated` |

### Grup manual

Grup juga bisa dibuat dari platform (console: kartu **Grup permission → Tambah grup**), dengan aturan
yang sama seperti permission manual.

| Method & path | Akses |
|---|---|
| `POST /api/v1/solutions/{solutionId}/permission-groups` | Platform admin |
| `GET /api/v1/permission-groups/{groupId}` | Token apa pun |
| `PATCH /api/v1/permission-groups/{groupId}` | Platform admin, hanya grup `manual` |

```json
{ "code": "report", "name": "Laporan", "description": "Export & rekap", "sort_order": 5, "parent": "hr" }
```

- `sort_order` opsional; tanpa nilai, grup tampil setelah grup terakhir.
- `parent` opsional: code grup **aktif** (sync maupun manual) di solution yang sama. Hierarki tetap maksimal
  3 level dan tanpa siklus — termasuk subgrup di bawahnya saat grup dipindah.
- `PATCH` mengubah `name`, `description`, `sort_order`, `parent` (`""` = jadi grup utama), `status`.
  `code` tidak bisa diubah.
- "Hapus" = `{"status": "deprecated"}`: grup tidak bisa dipilih untuk permission lagi, permission yang sudah
  ada di grup itu tetap tampil di dalamnya.
- Grup `sync` read-only di platform (`409`). Code grup manual tidak boleh dipakai di `groups` katalog sync
  (`409`). Permission hasil sync hanya bisa merujuk grup di katalognya sendiri; permission manual boleh
  memakai grup sync maupun manual.
- Grup manual boleh menjadi anak grup sync. Sync yang membuat grup manual seperti itu melewati 3 level
  ditolak `422`.

### Scope type manual

Scope custom juga bisa dibuat dari platform (console: kartu **Scope type → Tambah scope**), dengan aturan
yang sama.

| Method & path | Akses |
|---|---|
| `POST /api/v1/solutions/{solutionId}/scope-types` | Platform admin |
| `GET /api/v1/scope-types/{scopeTypeId}` | Token apa pun |
| `PATCH /api/v1/scope-types/{scopeTypeId}` | Platform admin, hanya scope type `manual` |

```json
{ "code": "project", "name": "Proyek", "parent": "company", "sort_order": 3 }
```

- Aturan `code` sama dengan `scope_types` di katalog (bukan `company` / `branch`); `parent` default
  `company`; `sort_order` opsional.
- `PATCH` mengubah `name`, `description`, `parent`, `sort_order`, `status`. `code` tidak bisa diubah.
- "Hapus" = `{"status": "deprecated"}`: tidak bisa dipasang ke permission role baru maupun dipakai
  assignment baru; yang sudah ada tetap dievaluasi.
- Scope type `sync` read-only di platform (`409`); code scope type manual tidak boleh dipakai di
  `scope_types` katalog sync (`409`). Permission role boleh memakai scope type sync maupun manual.

## Melihat katalog

`GET /api/v1/solutions/{solutionId}/permissions` — bisa dipanggil token apa pun.

Query: `status` (`active` / `deprecated`), `search`, `group` (code grup, termasuk subgrupnya; `-` = tanpa grup), `source`
(`sync` / `manual`), dan
pagination (`page`, `limit`, `sort_by`, `sort_type`).

```json
{
  "data": [
    {
      "id": "c0f1...",
      "solution_id": "6f1c0a52-...",
      "code": "employee.read",
      "name": "Lihat karyawan",
      "description": null,
      "status": "active",
      "source": "sync",
      "group": {
        "code": "employee", "name": "Data Karyawan", "sort_order": 1,
        "parents": [{ "code": "hr", "name": "Kepegawaian", "sort_order": 0 }]
      },
      "created_at": "...",
      "updated_at": "..."
    }
  ],
  "meta": { "current_page": 1, "per_page": 10, "total": 3, "total_pages": 1 }
}
```

`group` bernilai `null` untuk permission tanpa grup. `group.parents` = leluhur grup dari root sampai
induk langsung (kosong untuk grup utama) — cukup untuk membangun pohon di UI tanpa request tambahan.

Grup dan scope type:

- `GET /api/v1/solutions/{solutionId}/permission-groups` — `id`, `parent_id`, `parent` (code induk),
  `code`, `name`, `description`, `sort_order`, `status`, `source`.
- `GET /api/v1/solutions/{solutionId}/scope-types` — `company` dan `branch` (`builtin: true`,
  `source: "builtin"`) di depan, lalu scope type custom (`id`, `code`, `name`, `description`, `parent`,
  `sort_order`, `status`, `source`).

Keduanya menerima query `status` dan bisa dipanggil token apa pun.

`permission_catalog_version` pada [`GET /solutions/{id}`](/docs/onboarding-solution) menunjukkan versi
terakhir yang tersinkron.

## Error umum

| Status | Penyebab |
|---|---|
| `403` | Token service milik solution lain, scope `catalog:sync` tidak ada, atau user bukan platform admin |
| `404` | Solution tidak ditemukan |
| `422` | `version` kosong, `code` tidak sesuai pola, `name` kosong, atau `code` dobel di katalog |
| `409` | Katalog memuat code permission, grup, atau scope type yang dibuat manual di platform |
| `422` | `group` tidak ada di `groups`, `parent` grup tidak ada di `groups` / siklus / lebih dari 3 level, scope type `company`/`branch` didefinisikan ulang, `parent` scope type bukan `company`/`branch`, atau code grup / scope type dobel |
