## Format

```json
{
  "status": "error",
  "status_code": 409,
  "error_code": "ERR_CONFLICT",
  "errors": "Slug company sudah dipakai."
}
```

| Field | Isi |
|---|---|
| `status_code` | Sama dengan status HTTP |
| `error_code` | Kategori error (tabel di bawah). **Pakai ini untuk logika program.** |
| `errors` | Pesan untuk ditampilkan (string), atau objek `field → pesan` untuk error validasi |

Bahasa pesan mengikuti query `?lang=id|en`, lalu header `Accept-Language`, lalu default server.

::note
Penyebab detail (mis. "company belum dipilih" vs "bukan member") saat ini hanya muncul sebagai teks di
`errors`, belum sebagai kode terpisah. Jangan mencocokkan teks pesan di kode — bedakan kasus dari status,
endpoint, dan kondisi token (mis. ada/tidaknya `cid`).
::

## Kategori

| `error_code` | Status | Arti |
|---|---|---|
| `ERR_BAD_REQUEST` | 400 | Body bukan JSON valid, tipe field salah, body kosong |
| `ERR_UNAUTHORIZED` | 401 | Token tidak ada / tidak valid / kedaluwarsa / sesi dicabut; login gagal |
| `ERR_FORBIDDEN` | 403 | Token valid tapi tidak berhak (scope kurang, bukan admin, bukan member, belum pilih company) |
| `LICENSE_MANAGED` | 403 | Endpoint dikelola license (deployment `on_prem`) |
| `ERR_NOT_FOUND` | 404 | Data tidak ada, atau milik company yang tidak bisa Anda akses |
| `ERR_ROUTE_NOT_FOUND` | 404 | Path / method salah |
| `ERR_CONFLICT` | 409 | Duplikat (slug, code branch/role, member, assignment) |
| `ERR_UNPROCESSABLE_ENTITY` | 422 | Validasi gagal atau aturan bisnis menolak data |
| `ERR_INTERNAL` | 500 | Kesalahan server — aman di-retry dengan backoff untuk request idempotent |
| `ERR_SERVICE_UNAVAILABLE` | 503 | Layanan sedang tidak tersedia |

`POST /oauth/token` memakai format OAuth2 sendiri — lihat [Token service](/docs/service-token#error).

## Validasi field (422)

```json
{
  "status": "error",
  "status_code": 422,
  "error_code": "ERR_UNPROCESSABLE_ENTITY",
  "errors": {
    "email": "Wajib diisi.",
    "solution": "Wajib diisi."
  }
}
```

Petakan key `errors` ke field form. Error aturan bisnis (mis. "User bukan member aktif company ini.")
juga berstatus 422 tetapi `errors` berupa string.

## Pesan yang sering muncul

| Status | Pesan (`id`) | Kapan |
|---|---|---|
| 401 | Bearer token wajib disertakan. | Header `Authorization` tidak ada |
| 401 | Token tidak valid atau sudah kedaluwarsa. | Token rusak, expired, sesi logout |
| 401 | Email atau password salah. | Login gagal |
| 401 | Refresh token tidak valid atau sudah kedaluwarsa. | Refresh gagal / sudah dipakai |
| 403 | Pilih company aktif terlebih dahulu. | Token user tanpa `cid` di endpoint per-company |
| 403 | Anda tidak memiliki akses ke company ini. | `companyId` ≠ `cid`, atau bukan member aktif |
| 403 | Token service tidak memiliki scope yang dibutuhkan. | Scope kurang |
| 403 | Endpoint ini memerlukan token user. | Token service di `/auth/*`, `GET/POST /companies` |
| 403 | Memerlukan akses administrator platform. | Endpoint admin |
| 403 | Akun Anda tidak aktif. | Login user `inactive` / `suspended` |
| 403 | Company ini tidak bisa dipilih: ... | Switch ke company yang tidak aktif / bukan member |
| 403 | Hanya sesi console platform yang bisa masuk ke solution lain. | `POST /auth/authorize` dengan token selain sesi console |
| 422 | redirect_uri tidak terdaftar di solution ini. | SSO dengan `redirect_uri` yang tidak ada di allowlist |
| 400 | Kode otorisasi tidak valid, kedaluwarsa, atau sudah dipakai. ... | `POST /auth/token-exchange` gagal — ulangi SSO |
| 422 | User bukan member aktif company ini. | Assign role ke non-member |
| 422 | Role tidak tersedia untuk company ini ... | Role salah solution / company / sudah dihapus |
| 422 | scope_id bukan milik company ini ... | Branch salah di assignment / check |
| 422 | company_id dan user_id wajib untuk token service. | Authz check dengan token service |
| 422 | Satu atau lebih code permission tidak ada di katalog solution ini. | Replace permission role |
| 409 | User sudah memiliki role ini pada scope tersebut. | Assignment dobel |

Daftar lengkap ada di `locales/id.json` dan `locales/en.json` di repository platform.
